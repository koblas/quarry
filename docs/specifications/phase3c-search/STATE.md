## Binding decisions
- `report.Store.Search` runs exactly two statements: rows, then span. Predicates and args go through the one builder (`searchRowsQuery`/`searchArgs`), never a third statement; the unknown-category check is a third column of the span statement (SCENARIO-01, SCENARIO-04)
- The cut and `matched` happen at transaction grain inside the CTE (`count(*) OVER ()` before `LIMIT`), before the split join; `searchOrder` (date, source id, then `txn_id`, all DESC) serves the CTE and the outer SELECT. Counting after the cut, or a second copy of the order, double-counts splits or masks a mutation; dropping the `txn_id` tiebreak interleaves two transactions sharing date and source id (SCENARIO-01)
- `store.SearchWindow` open bounds are nil pointers, never a zero `time.Time`: `--since 0001` parses to exactly the zero time. Both bounds are civil days, inclusive (SCENARIO-01)
- Limit 0 binds nil to `LIMIT $3` (DuckDB 1.5, go-duckdb v2.10505.0: `LIMIT NULL` is no limit). `lower('CAFÉ') = lower('café')` holds, which retires S02's case-folding risk (SCENARIO-01)
- `transfer`/`excluded` flags come only from the fragments in `duckstore/schema.go` (`transferLeg(alias)`, `reportedTransaction`, `reportedAccount`), shared with `cashFlowViewDDL`; re-deriving either is a defect (SCENARIO-01)
- `SearchSplit.Transfer` means the split is a leg in `transfers`; a split with `transfer_account_id` but no transfers row is false (pinned in `duckstore/search_test.go`) (SCENARIO-01)
- `SearchParams`: `Text` ("" = none), `Min`/`Max` (`*int64` cents, nil = no bound), `Category *string` (nil = no filter). `Category` is `*string` end to end (`SearchParams`, `SearchRequest`, `report.Search`): `--category ""` is given-and-unknown, never "no filter"; the S09 handler passes the pointer through (a given `""` stays non-nil) (SCENARIO-02, SCENARIO-03, SCENARIO-04)
- `newSearchCommand(newReport, jsonOut)` takes no clock and no config loader (Rule S8, enforced by the signature); `--limit` flag default is 0 (so help prints no default) and `searchLimit` applies `defaultSearchLimit` = 500 unless `Changed`; negative is a `UsageError` (SCENARIO-01, SCENARIO-02)
- Help lists flags alphabetically like every sibling; no help pin asserts flag order (SCENARIO-01)
- Caption is `Transactions[ matching %q] in <accountsCaption>, <dates>[, category %q][, amount <range>]` (`searchCaption`/`searchDates`/`searchAmountRange`: `A to B`, `at least`, `at most`, `exactly` when equal). The footer counts `Matched`, not rows (SCENARIO-01, SCENARIO-02, SCENARIO-03, SCENARIO-04)
- Blank text is one rule: `report.CheckSearchText(*string)` / `ErrBlankSearchText` (TrimSpace==""), run in cobra `Args` (before RunE: before min/max, window, store open) and first in `Server.Search`. The MCP handler calls it first and `textRefusal` words it with `textRefusedLog` (SCENARIO-02, SCENARIO-10)
- Refusal order (Rule S9): `Args` (`searchArgs(&limit, category)`: count >1 text, negative `--limit`, blank text, text not UTF-8, `--category` not UTF-8), then RunE `searchAmounts` (min -> max -> min>max), `searchWindow`, store open, account, category, read. Pinned by `Test_run_search_refuses_in_the_ruled_order` (SCENARIO-02, SCENARIO-03, SCENARIO-04)
- Invalid UTF-8 text or category is `report.InvalidUTF8Error{Field, Value}` from `report.CheckUTF8`, a `UsageError` in cobra `Args` (exit 2, before the store); it is no `RefusalKind` and `Server.Search` does not call it, since the MCP decoder yields valid UTF-8. Text with NUL matches nothing and exits 0 (SCENARIO-04)
- `store.Search.UnknownCategory bool` is set by the span statement and `Server.Search` turns it into `RefusalError{Kind: RefusalUnknownCategory, Arg}` after the read (account resolution precedes; a sentinel from inside `duckstore.Search` would be wrapped into the "unknown error; rebuild" store line). MCP words it through `categoryRefusal` (`internal/mcp/accounts.go`: `no category named %q` from `refusal.Arg`, `Unwrap` keeps the class line `unknownCategoryLog`) (SCENARIO-04, SCENARIO-10)
- `report.ParseSearchAmounts(min, max *string)` is the only amount parser (nil = flag not given, `""` = given and refused; pointer from `Changed`, not `!= ""`). Grammar `^[0-9]{1,16}(\.[0-9]{1,2})?$`, cents `*int64`. Returns `AmountError{Kind, Bound, Value, Other}` by value; `Error()` is the CLI line. The MCP handler calls it after `CheckSearchText`, before `ParseSearchWindow`; `amountRefusal` words its lines from the parts (never string-replacing `Error()`, which has `--` and unquoted values the MCP lines do not) with `amountRefusedLog` (SCENARIO-03, SCENARIO-10)
- `Server.Search` trusts `SearchRequest.Amounts` (a Min>Max request matches nothing, is not refused): the check lives only in the parser because the refusal needs the raw strings and must beat a bad since (SCENARIO-03)
- Store binds, rows statement: `$1..$4` fixed, `$5` min, `$6` max, `$7` category (`searchCategory`), accounts from `$8` (`searchFirstAccount`); span statement: `$1` category, accounts from `$2`. Amount predicate is `abs(t.amount)` at transaction grain (never split amounts), inclusive, nil needs `CAST($n AS BIGINT) IS NULL`. Category predicate is an `EXISTS` over splits joined to categories: `lower(full_path) = lower($7)` or `starts_with(lower(full_path), lower($7) || ':')` (SCENARIO-03, SCENARIO-04)
- `document.Search.Min`/`Max` echo `document.Money(cents)` (`12.5` -> `"12.50"`), null when the flag is absent (SCENARIO-03)
- Text predicate is `contains(lower(..), lower($4))` over payee, `t.memo`, and an EXISTS over split memos (a JOIN would double-count `matched`); the bind is nil for "", so `$4` is cast in `CAST($4 AS VARCHAR) IS NULL` (SCENARIO-02)
- `document.SearchWarnings` is the only no-match composer (one line, four variants: store/named x span/none; `[]string{}` never nil); the MCP handler reuses it. The cut line `searchCutNote` is appended per surface after it, so CLI `--json` `warnings` equals the stderr lines; cut and no-match never coexist (SCENARIO-02)
- Memo ""→null is pinned at store level (`duckstore` `Test_search_gives_no_memo_for_a_null_or_empty_memo`), not in the document; `renderSearch` lists a transfer before a category and relies on the store contract that a transfer leg has no category (SCENARIO-01)
- Cell escaping (`escapeCell`: `\n`, `\t`, `\r`) applies to account, payee, category and memo (SCENARIO-01)
- MCP `search_transactions` handler order is `CheckSearchText` -> `ParseSearchAmounts` -> `ParseSearchWindow` (`windowRefusal`) -> `newReport` -> `Search` (`accountRefusal`) -> `NewSearch(found, SearchWarnings(found))` (Rule S9); each site is wrapped (`textRefusal`, `amountRefusal`, `windowRefusal`, `accountRefusal`, `categoryRefusal`), never reordered, pinned by `Test_run_mcp_search_transactions_refuses_in_the_ruled_order` (SCENARIO-09, SCENARIO-10)
- `searchInput` text/category/min/max/since/until are `*string`: nil = absent, `""` = given and refused; a `string` field loses that. `limit` schema `Default` 500 and `Minimum: 1` (`limitSchema`) are the only things keeping limit 0 ("no limit" in the store) off MCP (SCENARIO-09)
- MCP cut line (`searchCutLine`, `internal/mcp/search.go`) is appended after `SearchWarnings`, keyed on the limit asked (`== maxRows` narrow wording, less adds "pass a higher limit"); no `capList`, no clock, no config (Rule S7/S8) (SCENARIO-09)
- Tool description and parameter text are `tools.go` consts, byte-copied in `Test_run_mcp_describes_every_tool` (`mcpSearchDescription`/`mcpSearchInputSchema`, `mcpInstructions`, `mcpQueryDescription`, the `quarry mcp` Long fragment); edit const and pin together. Two specs cite that test (phase3b ticked it too) (SCENARIO-09, SCENARIO-10)
- Text and min/max class lines are `withLog` consts in `internal/mcp/result.go`, not `refusalLine` arms: an unwrapped blank text or `AmountError` falls to `failedLog`, so no caller value leaks. Invalid UTF-8 has no MCP wrapper or class line: pinned over stdio as a plain no-match result with empty stderr (SCENARIO-10)

## Traps
- `abs` must wrap `t.amount` (the transaction), never split amounts; a two-split transaction counts once in `matched`. The category predicate is likewise never `LIKE` and never a JOIN to the outer splits (SCENARIO-03, SCENARIO-04)
- `UnknownCategory` is read after the rows: a rows-statement fault on a store whose category is unknown prints the store line, not the category line; only fault injection reaches it (SCENARIO-04)
- The category is `$1` in the span statement and `$7` in the rows statement: mixing them breaks only when accounts are named (pinned by the combined-filter test) (SCENARIO-04)
- Two `// unreachable:` claims in `internal/report/amount.go` (`Error()` fallthrough, `parseAmountBound` ParseInt error) rest on the grammar and a grep of `AmountError{` constructors; a new constructor or a wider grammar voids them (SCENARIO-03)
- `transactionRange` (`duckstore/filter.go`) adds `reportedAccount` when accounts are named. Search's span must not reuse it, or a named left-out account says "they have no transactions" (SCENARIO-01)
- SDK rows (min as JSON number, limit 0, limit 501): assert the SDK text by field name only; the wording is the SDK's and `argumentsRefusedLog` is the stderr line (SCENARIO-10)
- The equality harness strips warnings: no-match identity is proven only by the explicit `toolWarnings == cliWarnings` assert in the S09 acceptance test; `fakeStore.Search` must cut to `params.Limit` or the cut line's "newest N" tests nothing (SCENARIO-09)
- `stallingStore.Search` (`internal/mcp/timeout_test.go`) must exist for the `search_transactions` timeout row, or the embedded nil `report.Store` panics (SCENARIO-09)
- `readCommandArgs` (`cmd/quarry/run_config_test.go`) must NOT gain search or mcp: search never reads config (pinned by `Test_run_search_ignores_a_malformed_config`, whose mutant is the factory loading config) (SCENARIO-02)
- `contains(NULL, x)` is NULL: the OR-chain is safe, never negate it. A nil bind to `$4` needs the VARCHAR cast (SCENARIO-02)
- Named left-out account: `SearchWarnings` says "their transactions run" off the unfiltered span; it must not use `appendEmptyWindowWarning` (skips left-out accounts) (SCENARIO-02)
- `internal/report/fakes_test.go` implements `report.Store` explicitly (cli/mcp fakes embed it), so a new Store method needs a stub there to compile (SCENARIO-01)
- Key order of the search document is seen only by the `document` byte-literal test (`//nolint:testifylint`: `JSONEq` is blind to order; `golangci-lint run --fix` rewrites it to `JSONEq`, undo that); the cmd decode is blind (SCENARIO-01)
- Row loops over `*sql.Rows` need a per-row `ctx.Err()` check (`rows.Err()` misses a cancel); `platform/sqlite` `QueryRows` still lacks it (unowned) (phase3b)
- `go test -run 'Window'` is case-sensitive; use `(?i)window` (phase3b)
