## Handoff

**Binding decisions** — a later scenario must not contradict these without saying so:
- data_quality loads config BEFORE opening the store (the CLI `findings` order, `cli/findings.go:78-90`); sync_status does the reverse. Cross-tool no-store/refusal tables (S13) must not assume one order.
- The findings and items caps live in `internal/mcp/data_quality.go`, applied to the listing before `document.NewFindingsList`; `counts` and `Unmatched` always from the uncut listing. `report` and `document` stay cap-free so `findings --json` is unchanged.
- Config refusal text is the loader's error verbatim (it already carries the `~` form and `; fix the file and run the command again`); no mcp copy for it.
- `status`/`limit` defaults come from the schema (`default` + `absentNullArguments` + SDK default step); the handler adds none. `absentNullArguments` must stay, or `null` panics the server.

**Left unbuilt** — named so nobody assumes it exists:
- `data_quality stopped after 30 seconds; try again` and deadline/cancel mapping — S06.
- data_quality row of the cross-tool no-store/refusal table — S13 (S11 pins config and store faults through the handler, not the no-store line).
- Any new `findings`/`document` field for cut or total counts — ruled out (Rule 6: warnings only).

**Traps** — things that look right and are not:
- `status=all` and `limit`=500/`type`-given wording of the findings-cap line is unruled; do not hand-pick at the keyboard, take the orchestrator's ruling.
- A handler-side default for `status`/`limit` looks safe and is dead code behind the SDK default step; the null/omitted/`{}` test is what proves the defaults arrive.
- `fakeStore` embeds `report.Store`: any test reaching `Findings` before step 2 adds the method panics.
- An uncategorized finding is per payee, items per split: the heavy-payee fixture needs a transaction whose entries sum to its amount, and a stray payee-variants or duplicate finding changes the totals.
- Slicing `Items[:25]` aliases the store's array; copy so a second call (or a test reusing the fixture) is not affected.
