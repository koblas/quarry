# Retro: mcp-install

Findings are MINOR by construction: they change the pipeline, not this feature. Sources: METRICS.md, REVIEW-01..04, STATE.md.

## Where the tokens went
Subagents 13,120k IE; orchestrator upper bound 3,925k (23% of 17,045k total). Developer 66% of subagent cost (26 runs, median 308k), architect 14%, test-reviewer 13%.
- Three most expensive scenarios: SCENARIO-04 2,071k, SCENARIO-01 1,952k, SCENARIO-10 1,753k. Feature-wide ("-") units cost 3,459k (26%), almost all of it the four gate-fix runs.
- Fix passes: gate-fix 1,615k (12%) + checkpoint-fix 158k (1%) = 13% of subagent total. Gate-review was 8% and the 2,249s mutation sample cost no tokens but most of the wall clock of round 1.
- Cadence: test-first 10 and 12 (1,753k / 1,566k) were not cheaper than code-first 01 and 04 and still drew 1 checkpoint MAJOR each; the deletion-guard rule was satisfied but did not show a cost win. Sonnet architect for 12 and 17: 17 was cheapest (1,096k) and clean (0/0/1/4). 12 was sonnet-planned yet shipped the two final-pass copy MAJORs; the cause was routing (finding 2), not planning, so no evidence against sonnet at this size. Keep it.

## What reached the final gate that an earlier stage owned
1. Gate R1 MAJOR, lists decoded from combined stdout+stderr (`state.go:396`). The seam was ruled at scoping, SCENARIO-01 shipped the reader and SCENARIO-04 built the adapter. Neither plan listed the cross-scenario invariant "decoders read stdout only; the Runner returns both streams". Owner: architect (plan gap). The first scenario to consume a seam cannot see the adapter built two scenarios later.
2. Gate R1 MAJOR, `toolrun.Run` output unpinned on exit/signal/cancel returns, then R2 MAJOR, same defect one level down (pins could not tell combined from stdout). Owner: SCENARIO-04 checkpoint, and `build.md` *Planning* (:88-108) has no bullet for "adapter returns two or more outputs: each return path pins every value". The fix pass fixed one of three return paths, so a second round (2 more fix passes) was a per-site patch, the exact pattern *Fix passes* "Two components disagreeing" warns of.
3. Final-pass copy changes (Kept line "a single project"; R6 hint advising `--scope` for rejected scopes) shipped by SCENARIO-12. METRICS says the copy was flagged at 12's checkpoint, but as pin-only/MINOR it went to `V`/STATE and the contradiction with ruled hints survived. Owner: checkpoint routing. Copy that contradicts another ruled string is wrong output, not a pin.
4. Gate R4 MAJOR (allow-list mutant in `remainingCopyHint`): the fix pass 3 added a branch with only named-scope rows. This is the "No new behaviour / positive assertion + out-of-domain row" rule in `build.md` *Fix passes* (:110-120) and *Planning* "out-of-domain row" not applied to a fix brief. Deferred under cap, which is working as designed.

Why four rounds: R1 two MAJORs (1 prod-design, 1 test) -> fix 1; R2 test MAJOR from an incomplete pin fix -> fix 2; R3 PASS; final product-vision pass -> fix 3 introduced R4 MAJOR -> cap hit. Two of the four rounds are consequences of incomplete fixes, not new finds.

## Ranked recommendations
1. **Fix `mutation-sample.py` timeouts (13/20 mutants, 2249s wasted, no signal).** Cause: `.claude/scripts/mutation-sample.py:248` runs every dependent package's tests (including `cmd/quarry`, ~150s) under a flat `--timeout` default 120 (:205), so any mutant in a package imported by `cmd/quarry` times out unless killed first. Reviewer had to "judge by reading" 13 mutants. Fix: (a) at the baseline step (:229) time each package separately and record seconds; (b) at :248 run dependents one `go test -failfast` per package, fastest-first, owning package first, and stop at first failure; (c) per-package timeout = max(`--timeout`, 3 x its baseline) instead of one flat value; (d) report a `timed out` mutant as a distinct warning count that the orchestrator must treat as a failed tool run (exit 2) when > 25% of the sample, instead of a silent exit 0. Update `.claude/commands/run-reviewers.md:107-115` ("Worst case is `--max` x `--timeout`") to the new bound, and the summary-line description there.
2. **Checkpoint routing for ruled-copy contradictions** — `.claude/briefs/build.md:70` (*Developer runs*, "Checkpoint findings route by what their fix touches"). Add: a finding that a string contradicts another ruled string in `## Surface & Copy` or a sibling hint is a production change (MAJOR, fix pass or `V` production step), never "pin-only". Evidence: Caught late rows 4 and 5 (both final-pass, SCENARIO-12), 2 gate-fix passes avoided at ~1.6M IE/4 passes average ~400k each.
3. **Cross-scenario seam invariant in the sizing pass** — `.claude/agents/architect/Agent.md:72-105` (sizing pass) and the spec `### Seams` template. When a seam is shared by scenarios built at different times (reader in 01, adapter in 04), the sizing pass writes the invariant ("decoders read stdout only") into the spec as a binding line and the earlier scenario's plan pins it with a fake that returns stdout != combined. Would have removed the R1 correctness MAJOR (its fix touched production, STATE, spec: fix pass 1, the most expensive).
4. **New *Planning* bullet: adapter with several output channels** — `.claude/briefs/build.md:~100` (after "One fault test per classified reason"). "A function returning more than one value derived from the same source (stdout, combined) pins each value on every return path (success, non-zero, signal, cancel) with inputs that make the values differ." Would have removed R1 test MAJOR and R2 MAJOR (fix passes 1 and 2 partly).
5. **Fix-pass brief for pin-only MAJORs must enumerate sibling return sites** — `.claude/briefs/build.md:110-120`. Extend "Membership-rule fix" with "pin fix on one return/branch lists every sibling return/branch of the same function (`file:line`)". R2 existed because fix 1 pinned one of three.
6. **Fix-pass cap and pin-only MAJORs** — `CLAUDE.md` *Fix passes capped at 3*. R4's deferral of a pin-only MAJOR left the verdict "PASS WITH FOLLOW-UPS (by cap rule; test-reviewer's own verdict was BLOCKED)". Acceptable, but state in the rule that pin-only findings fold into the next feature's first test touching the file (STATE.md already does this), so the debt has an owner.
7. **Metrics ledger**: `.claude/briefs/metrics.md` "Mutants (survived / sampled, secs)" cell had to carry "7 killed, 13 timed out"; add timed-out count as a fourth term in the template so it cannot be read as 0 survivors = clean.
