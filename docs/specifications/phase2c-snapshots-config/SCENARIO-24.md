## Handoff

**Binding decisions:**
- `PlanPrune` is a second method, `Prune(ctx, keep)` keeps its signature (34 test call sites) — SCENARIO-29 reuses neither; it marks from the built snapshot's path and calls `selectPrune` + delete itself.
- `Pruned` is the one fact record for text and JSON: `DryRun`, `WouldDelete`, `Deleted`, `Failed`, `StoreKept`, `StorePath` — SCENARIO-28 renders only; `Deleted` and `WouldDelete` are never both non-empty; a dry run leaves `Deleted`/`Failed` nil.
- `Pruned.Keep == 0` means "refused, nothing to report" in `RunE`; `PlanPrune` must keep returning zero `Pruned` on every refusal.
- The dry-run "nothing selected" outcome reuses the ordinary `Nothing to delete: …` lines: U7 and the Further-outcomes table rule that all apply to `--dry-run` too.
