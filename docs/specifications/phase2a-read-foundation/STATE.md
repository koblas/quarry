# phase2a-read-foundation — current state

Scenarios complete: SCENARIO-01..08 (05 folded into 04, 06 into 07). Last updated by SCENARIO-08.

## Binding decisions
- `store_info(format_version INTEGER, quarry_version VARCHAR, built_at TIMESTAMP)`, one row, appended LAST in `duckstore.build`: a store carrying it is complete. `duckstore.FormatVersion = 2` is the only definition; S15/16's format check compares against that symbol, never a literal. `built_at` is `Replace`'s own `time.Now().UTC()`, `>= import_runs.finished_at`; `status` shows `built_at`, never `finished_at`. TIMESTAMP is microsecond UTC: assert `>=`, never `>`. (S01)
- `quarry_version`: `duckstore.WithQuarryVersion(v)` (empty keeps `(devel)`), wired in `newServerFactory` via `buildVersion(debug.ReadBuildInfo())`. (S01)
- `import_runs` nullable columns: `snapshot_taken_at`, `source_path`, `balances_never_reconciled`, `investment_accounts`, `transfers_paired`, `transfers_cross_currency`. NULL `snapshot_taken_at`/`source_path` is legal; the read maps them to zero `TakenAt` / `""`, the four count columns via `COALESCE(..., 0)` (proved: `Test_status_reads_null_check_counts_as_zero`; Replace never writes NULL there). Snapshot ref values are the manifest's recorded ones (also under `--from`). (S01, S02)
- Transfers invariant `transfers_rows = paired + one_sided` is `importer.checkTransferTotals`, an error not a panic (a Go panic exits 2 = usage code). (S01)
- Read side: every Phase 2 read command lives in `internal/report`; its port `report.Store` (one method per read; `Status`, `Accounts`, `Query`) is implemented by the one `*duckstore.Store` (guard in `cmd/quarry/run.go`), by `fakeStore` in `internal/report/status_test.go` and `fakeReportStore` in `internal/cli/accounts_test.go` (both record Query's `maxRows` through a `gotMaxRows *int` every Query-calling test must set). Reads go through unexported `(*duckstore.Store).openRead` over the exported `duckstore.ReadDB` port (`QueryRows`, `QueryTable`, `Close`; fault seam `duckstore.WithOpenReadOnly`; `spyReadDB` in `status_test.go` overrides both query methods); S12 lockdown and S15-17 format/missing/corrupt refusals land in `openRead` (or `duckdb.OpenReadOnly`) once. A read never creates the store or its dir (proved: `Test_status_fails_on_a_missing_store_without_creating_it`, `Test_run_status_fails_without_creating_a_store_when_none_exists`). `docs/adr/003-duckstore-owns-the-read-side.md`. (S02)
- `store.Status{Path, FormatVersion, QuarryVersion, BuiltAt, Run ImportRun, FirstDate, LastDate}` carries everything `status --json` needs. Splits checked = `Run.Counts.Transactions`; snapshot id = `report.SnapshotID(Run.Snapshot.Path)` (S15's R2 reuses it). `FirstDate/LastDate` are calendar days (zero = no transactions): format `2006-01-02` as-is, never `.In(time.Local)`; only `taken_at` converts to local. (S02)
- One investment predicate: `store.IsInvestmentAccount` / `store.InvestmentAccountTypes()` (a func returning a fresh slice, consts `store.AccountTypeBrokerage`/`AccountTypeRetirement`) feed both the importer's balance gate (`import_runs.investment_accounts`) and the view's NULL balance - change one and `status` and `accounts` disagree. (S04)
- `v_account_balances(id, source_id, name, type, currency, institution, closed, active, balance)` is created in `build`'s one schema `Exec` (`schemaDDL+accountBalancesViewDDL()`), before `store_info`. Public contract for S08's `quarry sql` users and S07's JSON keys. `balance` DECIMAL(18,2): NULL only for investment types (even with transactions), `0.00` for none; only `date <= current_date`, filtered in the JOIN so a future-only account still lists. (S04)
- `(*duckstore.Store).Accounts` → `store.AccountList{AsOf, Accounts []store.AccountBalance{Account; Balance *int64}}`: one statement, a one-row `current_date AS as_of` driver LEFT JOINed to the view (AsOf present for zero accounts; S07 renders `AsOf`, never re-queries), `ORDER BY lower(name), name, source_id`, balance cast to BIGINT cents in SQL. It returns every account; the closed filter is `(*report.Server).Accounts(ctx, includeClosed)` returning `report.AccountListing{store.AccountList; Hidden int}` (`Hidden` = closed accounts filtered, 0 under `--all`; `AllHidden()` = `Hidden>0 && no accounts left`) - do not push the filter into SQL; P2a-3 reuses `Hidden`. (S04, S07)
- `accounts` table: `renderAccounts(store.AccountList)` (`internal/cli/render_accounts.go`) pads by rune count, Balance right-aligned (`formatMoney` or `not imported`), header always (incl. Status), no trailing spaces when Status empty; `accountStatus`: closed wins over inactive. `newAccountsCommand(newReport, jsonOut)` branches once, writes stdout, then writes `"quarry: "+note` to stderr only if stdout succeeded; the note text (`allClosedNote(hidden)`, N>=2 via `accountsPhrase`, exactly-1 copy) is the same string in `warnings[]` and stderr, in human and `--json`. (S04, S07)
- `accounts --json` = `renderAccountsJSON(store.AccountList, warnings)` (`json_accounts.go`): `accountsDocument`/`accountRowDocument` are distinct from sync's `accountDocument`; `as_of` formatted as-is; `accounts` built with `make` so zero is `[]`; empty institution string maps to `null` (an institution row with an empty name is possible). (S07)
- `sql` path: `(*duckdb.DB).QueryTable(ctx, query, maxRows)` runs the query verbatim (never rewritten or wrapped) and returns the driver error unwrapped; `(*duckstore.Store).Query` wraps open/query faults once `run query: %w` (S12's classifier reaches `*duckdb.Error` via `errors.As`); `(*report.Server).Query(ctx, query, limit)` owns the limit rule (fetch `limit+1` when `0 < limit < MaxInt`, else 0 = all; `report.QueryResult{store.QueryResult; Truncated}`); cli `newSQLCommand(newReport)` renders `renderSQLTable` (`render_sql.go`). S09 renders the warning / `truncated` / `limit` from `Truncated` and never touches the query path. (S08)
- Cells: `store.QueryValue{Null, Text, Native}` filled in one pass by `duckdb.cellValue`. `Text` = DuckDB's `CAST(x AS VARCHAR)` text, `"NULL"` for NULL, UNESCAPED (cli escapes only `\n \t \r`, widths measured after). `Native` = nil | bool | int64 (signed ints) | uint64 (unsigned) | float32 (FLOAT) | float64 (DOUBLE; NaN/±Inf kept) | `time.Time` UTC for finite DATE, TIMESTAMP, `_S/_MS/_NS`, TIMESTAMPTZ | `Text` string for everything else incl. DECIMAL, HUGEINT, UHUGEINT, BIGNUM, ±infinity dates. S09 encodes JSON from these + `QueryColumn.Type`, no re-query. (S08)
- Rendering dispatches on the Go value, consulting the column type parsed from `DatabaseTypeName` (`duckdb.parseTypeName` → `typeNode` tree, `typename.go`) where Go type is ambiguous: UUID vs BLOB (`[]byte`), date/time kinds (`time.Time`), STRUCT field order (declared order; sorted by name only when the type name does not parse or does not name the value's fields), UNION member type. Nested leaf text is quoted per DuckDB (empty, edge whitespace, `null` any case, or one of `"'(),:=[]{}`; `\`→`\\`, `'`→`\'`); NULL, nested containers and UNION values never quoted. Oracle: `Test_query_table_text_matches_duckdb_cast` (95 rows, one per type/edge). (S08)
- Q5 plumbing: renderer refusal → `*duckdb.UnprintableValueError{Column, Type}` → duckstore maps to `*store.UnprintableValueError` (returned unwrapped) → cli `queryFailure` appends `; cast it in the query, e.g. CAST(<name> AS VARCHAR)` via `%w`. Reachable for real: a `JSON` column (the driver hands over decoded JSON; ruled as Q5 by the developer, not by product-vision) - `Test_query_refuses_a_value_it_cannot_print`. S12's classifier must keep this branch ahead of its `run query:` handling. (S08)
- Numeric = `store.QueryColumn.Numeric()`, regexp anchored on the whole type name (ints incl. HUGEINT/U*/BIGNUM, FLOAT, DOUBLE, `DECIMAL(w,s)`); numeric columns and headers right-aligned. (S08)
- `FormatVersion` stays 2 (format 2 unshipped): a dev store built before S04 lacks the view - catalog error until re-sync. (S04)
- JSON documents live in `internal/cli/json*.go`; `marshalDocument(doc any)` (json.go) is the ONE encoder (2-space indent, trailing newline, the single `// unreachable:` line) for sync, status, accounts; S09's `sql --json` goes through it. Conventions: pointers for nullable fields (`jsonNullString`, `jsonNullTimestamp`, `jsonNullDate`), `[]T{}` never nil, `.UTC().Format(time.RFC3339)` for times, `2006-01-02` as-is for dates, paths absolute (no `homepath.Abbreviate`). `status --json` (`json_status.go`) reuses `rowsDocument`/`notImportedDocument`; its `balances`/`splits`/`transfers` are int-only types distinct from sync's list-carrying ones. `warnings` is `[]string{}` unless a note applies (accounts). `newStatusCommand(newReport, jsonOut)` branches once and writes once. (S03)
- cli/cmd seams, widened once: `cli.Env{Stdin, Stdout, Stderr, NewServer, NewReport}`, `cli.Execute(ctx, args, env)` (also `SetIn`), `cli.ReportFactory func(ctx, command string)` - the command name reaches the factory so H1 is one builder (`resolveHome(command)` in `cmd/quarry/run.go`, sync passes `"sync"`, text byte-identical). `runWith(ctx, args, env)`, `defaultEnv(stdout, stderr)`, `newReportFactory(storeOpts...)`, `storeDirUnder(home)`. `run()` wires `os.Stdin`, so S18's stdin tests go through `runWith` with `env.Stdin` overridden. (S02)
- Phrase functions take counts, not check slices: `transfersPhrase(paired, oneSided)`, `balancesPhrase(checked, neverReconciled, investment)`, `splitsPhrase(checked)`; `sync` and `status` share them, plus `rowsPhrase`, `formatMoney`, `humanize`, `homepath.Abbreviate`. Age is floored per bucket, negative age is `just now`, the smallest day count is 2. (S02)
- Phase 1 seams still binding: `duckstore.DB` port + `WithCreate` are the build fault seam; `internal/store` holds driver-free values only (ADR-001); `Replace` swaps atomically and never opens the final path, so a concurrent reader sees the old inode. (Phase 1)

## Traps
- The test binary's `debug.ReadBuildInfo().Main.Version` is `""`/`(devel)` either way: no `cmd/quarry` test can tell "wired" from "not wired". (S01)
- DuckDB's `InstanceCache` refuses a second differently-configured open of one path in-process while the first is live: fixtures writing at the final path must Close first. A cmd-level `OpenReadOnly` after `status` cannot detect a leaked connection; only the fake-DB Close test (`Test_status_closes_the_connection_on_success_and_on_a_query_fault`) proves Close. (Phase 1, S02)
- `QueryRows` with zero rows leaves the scan targets untouched and returns nil - hence `Status`'s found-exactly-one-row check; `min/max(date)` over no transactions returns one NULL row (scan into `sql.NullTime`). (S02)
- `balances.never_reconciled` is an int in status JSON but a list in sync's: reusing `balancesDocument` emits the wrong shape. `rows.transfers` is `Counts.Transfers`, `transfers.paired` a smaller count: keep one-sided > 0 in fixtures. `quarry_version` in `--json` is proven only by `(devel)` shape at cmd level. (S03)
- `t.Setenv("TZ")` does not reset `time.Local`; render tests swap `time.Local` with `useZone` (`render_status_internal_test.go`, never in `t.Parallel` tests) and every `time.Local` use needs `//nolint:gosmopolitan`. (S02)
- `v9fixture` writes `ZQUICKENID` raw: give every transfer leg a distinct non-zero `QuickenID`; paired = mutual numeric `Transfer` links; a text `Transfer` ("Old Visa") makes a one-sided leg. `fakeStore` (importer tests) captures `Rows` by value: assert `ImportRun` field-wise. (Phase 1, S01)
- `SUM(DECIMAL(18,2))` is DECIMAL(38,2), which the driver will not scan into int64: cast to BIGINT cents in SQL. Importer dates are UTC calendar days, `current_date` is process-local: date-boundary tests belong at duckstore level with `store.Transaction.Date` = local Y/M/D at UTC midnight; cmd fixtures use dates a year ahead. A retirement account with no transactions reads "not imported" whether or not the predicate works: fixtures give it one. (S04)
- Without the `source_id` tiebreak DuckDB's order of same-name accounts is nondeterministic (probed): `Test_accounts_sorts_by_name_then_source_id` uses three same-name accounts inserted and id-named opposite to source id, red 20/20 under the mutation. (S04)
- Go 1.27 `modernize`/embedlit wants promoted fields in `store.AccountBalance{ID: ...}` literals, not `Account: store.Account{...}`; `golangci-lint run --fix` rewrites them. testifylint wants `JSONEq` unless the bytes are the contract (`//nolint:testifylint` with reason). (S04, S07)
- `nil[:0:0]` is nil: zero accounts reaches cli as a nil slice; a `[]T` built by append encodes `null`. `as_of` is process-local `current_date`: the cmd test tolerates a midnight rollover. (S07)
- `sql` table vs DuckDB (declared divergences, none ruled by product-vision beyond STRUCT's fallback): `TIME '24:00:00'` prints `00:00:00` (the driver collapses it before quarry sees it; pinned by `Test_query_table_prints_time_24_00_00_as_midnight`); TIMESTAMPTZ renders in `time.Local` (DuckDB's default TimeZone), so a `SET TimeZone` in the same query string is not followed; a value's own trailing spaces are kept (only padding is trimmed; no test pins this). (S08)
- Until S12 the READ_ONLY-only DSN lets `sql` run `COPY ... TO '<file>'` and `read_csv('<file>')`; no S08 test relies on external access. DuckDB materialises results, so an `error()` raised mid-result surfaces at Query, not `rows.Err`; `rows.Err` is reached by a `VARIANT` column (`Test_query_table_returns_the_driver_error_for_a_type_it_cannot_read`). S09: `encoding/json` refuses NaN/Inf - `marshalDocument`'s `// unreachable:` line becomes reachable. (S08)
- `uncovered-diff.py` is blind to untracked files: `git add` before running it. `cmd/quarry`'s test binary links DuckDB (linux-small CI OOM history). `internal/platform/duckdb`'s mid-iteration ctx-cancel test flakes under full-suite load. (Phase 1)
