## Traps
- Q-sentinels wrap `%w: %w`, so `errors.Unwrap` returns nil on them: reach a wrapped error with `errors.As`/`errors.Is` tree walks, never a single-chain `errors.Unwrap` loop. (S12, S15)
- Driver messages name the store by its RESOLVED path (`/private/var/…` on macOS) while `Path`/`$HOME` is `/var/…`, a substring of it: replace resolved → `Path` first, then `Path` → `~`; reversed yields `/private~/…`. Linux `t.TempDir()` has no symlink - reason tests symlink the store dir. (S15)
- R3c needs ANOTHER process: an in-process second open fails with InstanceCache's `different configuration`, not `Could not set lock on file`. `Test_open_read_only_on_a_file_another_process_holds_classifies_as_locked` re-execs the test binary (`Test_hold_a_database_open_for_writing`, env-gated skip). `chmod 0000` file: stat succeeds, driver `Permission denied` (R3b); `0000` dir: stat is `EACCES` (not missing) → driver R3b; empty file = not-a-database (R3a); store path a directory = R3 `Could not read from file "…": Is a directory`. (S15)
- duckstore fakes: `spyReadDB` lets openRead's format checks (`duckstore.FormatCheckQueries`, `export_test.go`) reach the real DB (`spyOpener` over a built store) and faults only the read's own query; `checkFaults[query]` faults one check; `onQuery` runs as the read's own query starts. A pre-cancelled ctx now fails at the open (Ping), so a query-stage interrupt test must cancel from `onQuery`. An injected opener on an empty dir never runs (stat → missing): give it a store file. (S15)
- A held reader shares DuckDB's `InstanceCache` entry: close it before a fresh `openRead`, or the fresh read may be served the old inode. chmod-based tests call `skipAsRoot(t)` (new-in-2a ones only; Phase 1's do not). (REVIEW-01)
