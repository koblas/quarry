## Binding decisions
- `internal/quicken/v9` (+ `v9fixture`) is a data package; production `internal/snapshot` never imports it. The reference schema arrives via `WithReference(label, sqlschema.Schema)`; `cmd/quarry` is now the one production caller of `v9.Reference`/`v9.ReferenceLabel`. (SCENARIO-01a)
- BR-6 scope lives in unexported `snapshot.scopeSchema`; `sqlschema` stays generic (no Quicken knowledge). Fingerprint and diff both run on scoped schemas. `SchemaInfo.ReferenceTables`/`ReferenceColumns` (`json:"-"`) are the scoped reference's counts, computed once in `schemaInfoFromDiff` for the CLI's human Schema line. (SCENARIO-01a, 01b)
- `Source` (`Open`/`Probe`/`Backup`/`Close`) and `Destination` (`Prepare`/`Backup`/`WriteManifest`/`CommitSnapshot`/`CommitManifest`/`FinalPaths`/`Discard`) are the only two ports in `internal/snapshot`. `Destination.Backup(ctx, src, name) (partial, resolvedName string, err error)` returns the name it actually reserved — `name`, or `"<name>_2"`, `"<name>_3"`, ... on a same-second collision (the Files-on-disk "Same-second collision" row, SCENARIO-11) — and `Sync` calls `FinalPaths(resolvedName)` only *after* `Backup` returns, never on the pre-collision name it computed from `time.Now()`. `Discard(ctx, partial) error` removes a snapshot partial `Backup` created; `Sync` calls it only on a `buildManifest` failure, treating its own error as best-effort (never overrides the classified refusal) — every `Destination` implementer, fakes included, must add it. Production adapters are unexported (`newSQLiteSource`, `newDirDestination`); `internal/snapshot/export_test.go` re-exports them as `NewSQLiteSource`/`NewDirDestination` for the `snapshot_test` package only. Both are injectable in production via `WithSource`/`WithDestination`. (SCENARIO-01a, 01b, 08, 11)
- `Manifest.Encode()` is the only encoder (2-space indent, trailing `\n`); the four diff lists are always non-nil empty slices, never `null`. (SCENARIO-01a)
- `Sync`'s order is: reference check → `Source.Open` → `Source.Probe` → `Destination.Prepare` → `Destination.Backup` → integrity check → `ZACCOUNT` exists → `ZACCOUNT` count ≥1 → SHA-256 → schema diff → `Encode` → `WriteManifest` → `CommitManifest` → `CommitSnapshot`. Manifest commits before snapshot. Nothing touches the snapshots directory before the probe succeeds. On any content-check failure, `Sync` calls `Destination.Discard` then returns `contentRefusal`. This same order, plus `atomicfile.Commit`'s link-then-remove, is what makes `dirDestination.Backup`'s reservation loop race-safe: a rival's partial is removed only after both its finals exist, and a final becomes visible before its partial disappears — reordering either breaks the loop with no test going red. (SCENARIO-01a, 08, 11)
- `Sync` takes an already-resolved, absolute bundle directory path and joins `"data"` itself; it never resolves `~` or relative paths itself. (SCENARIO-01a, 01b)
- `internal/cli`: `Execute(ctx, args, stdout, stderr, srv *snapshot.Server, home string) error` builds a fresh `*cobra.Command` tree per call. `home` is resolved once in `cmd/quarry/run.go` via `os.UserHomeDir()` and passed in — `Execute` never reads the environment. `UsageError{msg}` (value type, not pointer) is a final exit-2 message; `Execute`'s default branch wraps any other cobra-native error as `UsageError{err.Error() + "; Run 'quarry sync --help' for usage."}`. `runtimeError` (unexported, `Unwrap`) marks a `ResolveBundlePath`/`srv.Sync` failure as already-classified; `Execute` unwraps it and returns the original error unchanged (exit-1 default in `cmd/quarry`). Root: `SilenceUsage`/`SilenceErrors`/`DisableSuggestions` true, `CompletionOptions.DisableDefaultCmd` true, `help` subcommand kept, no `Run`/`Args` on root itself. (SCENARIO-01b)
- `internal/cli/sync.go`'s `RunE` calls `snapshot.ResolveBundlePath(home, quickenPath)` before `srv.Sync`, wrapping either's error identically as `&runtimeError{}`. A refusal from `ResolveBundlePath` never reaches `Destination.Prepare`. (SCENARIO-05)
- `--quicken` is no longer `MarkFlagRequired`. `RunE` branches on `cmd.Flags().Changed("quicken")` between `ResolveBundlePath` and `snapshot.DiscoverBundle(home)`. `DiscoverBundle` (`internal/snapshot/discover.go`) finds the sole top-level `*.quicken` directory in `~/Documents`, then delegates its sole match to `ResolveBundlePath`. (SCENARIO-04)
- `internal/snapshot.ResolveBundlePath(home, path) (string, error)` (exported) resolves a `--quicken` value to an absolute bundle path: `homepath.Expand` → `filepath.Abs` → `os.Stat` → `.qdf`/`.QDF` suffix check → not-a-directory check → unexported `validateData`. `RefusalError` (`internal/snapshot`, value type, `Error()` excludes the `quarry: ` prefix) is the shape every final one-line refusal returns. (SCENARIO-05)
- `internal/platform/homepath` (`Expand`/`Abbreviate`, both `(home, path string)`) is the one seam for home-relative path text; `internal/cli` no longer owns a local `abbreviateHome`. (SCENARIO-05)
- `Server.home` (`WithHome`) and `Server.busyTimeout` (`WithBusyTimeout`, default `DefaultBusyTimeout` = 5s) are the two new `Server` fields. `home` is the seam every refusal raised *inside* `Sync` uses for `~`-abbreviation — R13/R14 reuse it, no separate seam. `busyTimeout` governs both `Source.Open`'s connection-level SQLite `busy_timeout` (via `sqlite.OpenReadOnlyBusy`) and `Source.Backup`'s own Go-level retry deadline (via `sqlite.Backup`/`runBackup` — the DSN param has no effect on `sqlite3_backup_step`). Not a CLI flag or config key in Phase 0. (SCENARIO-06)
- `internal/platform/sqlite.Backup(ctx, src, destPath, busyTimeout)` and its private `runBackup` retry on a not-done/no-error `Step` result: sleep `backupRetryInterval` (10ms) via a `select` that also watches `ctx.Done()`, until `busyTimeout` elapses (then returns a `sqlite3.Error{Code: ErrBusy}`) or `ctx` is cancelled (returns `ctx.Err()` unchanged). One ctx-check location only — a second, top-of-loop check was removed because the retry `select` already observes cancellation first in every real case; `uncovered-diff.py` caught the duplicate as dead. `sqlite.IsNotADB`/`IsBusy` classify a `sqlite3.Error` by code (`errors.As`); `IsBusy` covers both `ErrBusy` and `ErrLocked`. `sqlite.OpenReadOnlyBusy` is `OpenReadOnly` plus a DSN `_busy_timeout=<ms>` param (factored through a shared unexported `openReadOnly(ctx, path, dsn)`). (SCENARIO-06)
- `internal/snapshot/refusal.go`'s `sourceRefusal(home, bundlePath, err)` classifies a `Source.Open`/`Probe`/`Backup` failure: `sqlite.IsNotADB` → encrypted refusal, `sqlite.IsBusy` → busy refusal, else the unchanged `fmt.Errorf("sync %s: %w", bundlePath, err)`. It is Source-facing only — classifying a failure on the already-open **snapshot copy** (a different connection, opened via plain `OpenReadOnly`) is `content_refusal.go`'s `contentRefusal`, a separate function; a later scenario must not merge them. (SCENARIO-06, 08)
- `content_refusal.go`'s `contentRefusal(home, bundlePath, err)` classifies a `buildManifest` failure on the snapshot copy: `errors.As` into `sqlite.IntegrityError` (R10), `errors.Is(errNoAccountsTable)` (R11), `errors.Is(errNoAccounts)` (R12), else the same generic wrap `sourceRefusal`'s default arm uses. `sqlite.IntegrityCheck` returns a typed `IntegrityError{Result string}` — `Result` is PRAGMA's first row's last physical line, not the raw row (which can carry an embedded `\n`); callers must `errors.As`, never parse `Error()` text. `Sync` calls `destination.Discard` (best-effort) then `contentRefusal` on any `buildManifest` failure — an empty, `0700` snapshots directory is left behind (`Prepare` already ran). (SCENARIO-08)
- `outcome.go`'s `MismatchError` (M1) and `extrasWarningText` (W1) are BR-9's outcome policy: `Sync` sets `manifest.Warnings` from `extrasWarningText` only when the schema has unexpected tables/columns and **no** missing ones (`hasOnlyExtras`), and — after both files are committed — returns `(manifest, mismatchError(...))` instead of `(manifest, nil)` when `!manifest.Schema.Verified`. Both refusal builders call the one shared `sqlschema.CountPhrase(tables, columns int) string` ("N table(s) and M column(s)", zero-clause omitted); `internal/cli/render.go`'s `schemaLine` calls it too, so the phrase is worded once. (SCENARIO-10)
- `internal/cli/sync.go`'s `RunE` renders stdout (block or `--json`) from `srv.Sync`'s returned manifest in *every* case — success, extras-only, or mismatch — before checking the error; only `errors.As(err, &snapshot.MismatchError{})` decides whether it also returns `&runtimeError{err: err}` for exit 1. Any other non-nil error still short-circuits before rendering. `renderSuccess`'s Schema line and its `writeDiffRows` diff block (`-` rows before `+` rows, tables before columns, label field padded to 8) now render all three outcomes, not just the exact match. (SCENARIO-10)
- `dirDestination.Backup`'s reservation loop (`internal/snapshot/destination.go`) tries `name`, `name_2`, `name_3`, ... uncapped: `atomicfile.Create`'s `fs.ErrExist` (another sync's own partial still on disk) and an existing sqlite-*or*-json final (a committed collision) both advance to the next candidate; any other create error returns immediately. `dirDestination.Prepare`'s startup sweep removes only quarry-pattern `.partial` leftovers (BR-14, `leftoverPartialPattern`) older than `leftoverMaxAge` (1h, a named constant) — a concurrent sync's own in-flight partial is always younger, so the sweep only ever reaches crash debris; `ReadDir`/`Remove` failures are swallowed. (SCENARIO-11)
- `destination_refusal.go`'s `writeReason(err)` unwraps any error to its innermost cause's message via a generic `errors.Unwrap` loop (covers `*fs.PathError`, `*os.LinkError`, `fmt.Errorf` `%w` chains with no type switch), falling back to `err.Error()` for a real sqlite disk-full error. `prepareRefusal` is always R13 (`Destination.Prepare` failure); `writeRefusal` is every later write failure — R13 when `errors.Is(err, fs.ErrPermission)`, else R14. `Sync`'s `Backup` call site checks `sqlite.IsNotADB`/`IsBusy` *before* `writeRefusal`, so a classified sqlite fault wins even if it's also a permission error. `Destination.Discard` now also runs (best-effort) on `WriteManifest`/`CommitManifest`/`CommitSnapshot` failure, discarding the manifest final before the snapshot partial when `CommitSnapshot` fails. (SCENARIO-13)

## Left unbuilt
- Busy timeout as a config key (Phase 1 obligation) — `DefaultBusyTimeout` stays a constant in Phase 0.
- `leftoverMaxAge` (1h) is a constant, not configurable — no scenario needs it to be; a crash debris file survives up to an hour before the next sweep reaches it.
- `v9fixture.MissingSchemaBundle`/`ExtraSchemaBundle` are SCENARIO-10's only fixture builders that mutate a real on-disk schema (drop/add real tables and columns via DDL); no other scenario needs them.

## Traps
- mattn/go-sqlite3's `Backup` is called on the **destination** connection: `destConn.Backup("main", srcConn, "main")`, not the other way around.
- A `database/sql.DB` pinned to `SetMaxOpenConns(1)`: never call a method that needs a pool connection while a `*sql.Conn` checked out from that same pool is still open — it deadlocks. Run the follow-up statement through the checked-out `*sql.Conn` itself.
- SQLite creates db files `0644`; pre-create the partial `0600` via `atomicfile.Create` (`O_EXCL`) before backing up into it.
- The backup API copies the WAL flag from the source header, so the destination needs `PRAGMA journal_mode = DELETE` before hashing, or it grows its own `-wal`/`-shm`.
- `atomicfile.Commit` is hard-link-then-remove, not `os.Rename` — refuses to clobber an existing destination atomically.
- `dirDestination.WriteManifest`'s `f.Write(data)` failure branch is permanently unreachable through the real adapter; marked `// unreachable` in code, not an open debt.
- `os.UserHomeDir()`/`v9.Reference(ctx)` failures happen in `cmd/quarry/run()` before `cli.Execute` runs — routing them through the `UsageError` check would wrongly exit 2 on an unset `HOME`.
- Cobra's `c.Find` failure (unknown command) returns a plain error straight from `ExecuteContext` — `Execute`'s default branch, not a named check, catches it.
- `SilenceErrors`/`SilenceUsage` on the root command alone suppress printing for every subcommand.
- Cobra falls back to reading `os.Args` when `SetArgs(nil)` — `Execute` requires a non-nil `args` slice and does not normalize.
- A pre-cancelled or expired `ctx` reaching `v9.Reference` fails at `sqlite.OpenMemory`'s `PingContext`. Don't mark a ctx-consuming call `// unreachable` on the strength of "no external resource can fail" alone.
- `v9fixture.CorruptDataFile`'s corruption trick only works on a database it built itself (`ZACCOUNT`'s pages near the front, a large filler index owning the last pages) — never run it against an existing WAL-open fixture's `data`. A 0-byte `data` file opens, probes and backs up clean (a valid, empty 4096-byte DB) through the real `Backup`/`atomicfile` chain — it must never reach `sourceRefusal`'s encrypted branch. `IntegrityCheck`'s first PRAGMA row is header-plus-detail, plus a second, unread row, on both corruption recipes in this codebase — never treat the raw row as "the first result line", and never derive a test's expected text by reading `IntegrityError.Result` back from the code under test. A stub (no real `data` file) for a content-rejection acceptance row reddens at `ResolveBundlePath`'s R6, not at `Sync`'s content checks — the fixture must be real. (SCENARIO-08)
- Every fallible step in `Sync` now returns a classified `RefusalError`; the generic `fmt.Errorf("sync %s: %w", ...)` wrap survives only on the `// unreachable` `Manifest.Encode` branch. A new fallible step must be routed to a classifier, not left on that wrap, or the `sync <path>: ` prefix corrupts the exact-copy contract. Checking `sqlite.IsNotADB`/`IsBusy` *before* `writeRefusal` at the `Backup` call site is load-bearing: a `Backup` error can be both a classified sqlite fault and `fs.ErrPermission`, and only the source refusal is correct for it. (SCENARIO-13)
- `ResolveBundlePath`'s readability check is a plain `os.Open`+immediate-`Close`, never a read — closing any fd drops every fcntl lock the process holds, so running it after `Source.Open` would drop SQLite's lock mid-backup.
- `os.Stat` already follows symlinks; `ResolveBundlePath` does not `Lstat` or `filepath.EvalSymlinks`.
- mattn defaults every connection's SQLite `busy_timeout` to 5000ms **unconditionally**, regardless of DSN params — a lock held during a *regular* query (`Open`'s own probe, or any statement) waits out that default before failing. `sqlite3_backup_step` alone is exempt: it returns control immediately on BUSY/LOCKED with no C-level wait, which is why `runBackup` needs its own Go-level retry loop while `Open`/`Probe` do not. A test that wants a fast, deterministic busy failure through `Backup` must open the source via `OpenReadOnlyBusy` with a small timeout (or `0`), not plain `OpenReadOnly` — otherwise the connection's own default dominates the wall-clock time regardless of what's passed to `Backup`.
- A ctx-cancellation test for a retry loop needs the loop actually *waiting* (real contention) when cancel fires. A pre-cancelled ctx with no contention proves nothing: `database/sql`'s own `Conn(ctx)` rejects an already-cancelled ctx before the code under test is ever reached.
- `BEGIN EXCLUSIVE` must be left **uncommitted** for a lock fixture's whole test; committing early releases the lock before a deadline or assertion fires.
- M1 and W1 both name the **bundle** by `filepath.Base`, but differ on the other path: M1 gives the **snapshot** `~`-abbreviated (`homepath.Abbreviate`, like every R-series refusal), W1 gives the **manifest** as a bare `filepath.Base`. The W1 warning text excludes the *entire* "quarry: warning: " prefix (`RunE` prepends both words; `run.go` never does, unlike the error path). (SCENARIO-10)
- `ALTER TABLE ... DROP COLUMN` (SQLite ≥3.35, satisfied by mattn/go-sqlite3 v1.14.52) refuses a column that is a PK/UNIQUE/FK or referenced by a `CREATE INDEX`/trigger/view — a fixture that mutates `v9.ReferenceDDL` on disk must check `reference.sql`'s indexes before picking which table/columns to drop, and assert the delta via a direct schema query rather than trust the statement silently. (SCENARIO-10)
- `testing/synctest.Test` works cleanly against this package's real cgo/file-I/O backup path (mattn/go-sqlite3, no injected clock): two `Sync` calls back-to-back inside one bubble freeze to the identical `time.Now()`, giving a same-second collision without a manual timestamp. Build the fixture (`v9fixture.OpenBundle`, `v9.Reference`) *before* entering the bubble. (SCENARIO-11)
- `dirDestination.Backup`'s reservation loop has two independent collision checks that need separate tests: `atomicfile.Create` returning `fs.ErrExist` (another sync's own partial, not yet committed, already on disk) and the candidate's sqlite-or-json *final* already existing (a finished collision). A test proving one does not exercise the other, and `uncovered-diff.py` will flag whichever line is skipped. (SCENARIO-11)
- `os.MkdirAll` returns `nil` for an already-existing directory regardless of its permission bits — a test for a write failure on an already-`Prepare`d directory must pre-create the directory itself and `chmod` *that*, or `Prepare`'s own `MkdirAll` never reaches the real bug. (SCENARIO-13)
- `*fs.PathError` and `*os.LinkError` both implement `Unwrap`, so a single generic unwrap-to-root loop classifies either without a type switch — no separate branch, so no `// unreachable` default to justify later. Prefer this shape over `bundle.go`'s `osReason` (an `errors.As` type switch) for any new destination-side reason-extraction. (SCENARIO-13)
