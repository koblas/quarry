## Binding decisions
- `internal/quicken/v9` (+ `v9fixture`) is a data package; production `internal/snapshot` never imports it. The reference schema arrives via `WithReference(label, sqlschema.Schema)`; `cmd/quarry` is now the one production caller of `v9.Reference`/`v9.ReferenceLabel`. (SCENARIO-01a)
- BR-6 scope lives in unexported `snapshot.scopeSchema`; `sqlschema` stays generic (no Quicken knowledge). Fingerprint and diff both run on scoped schemas. `SchemaInfo.ReferenceTables`/`ReferenceColumns` (`json:"-"`) are the scoped reference's counts, computed once in `schemaInfoFromDiff`; `SchemaInfo.HasExtras()` is the one place both callers (`outcome.go`, `cli/render.go`) test for unexpected tables/columns. (SCENARIO-01a, 01b)
- `Source` (`Open`/`Probe`/`Backup`/`Close`) and `Destination` (`Prepare`/`Backup`/`WriteManifest`/`CommitSnapshot`/`CommitManifest`/`FinalPaths`/`Discard`) are the only two ports in `internal/snapshot`. `Destination.Backup` returns the name it actually reserved (`"<name>_2"`, ... on a same-second collision), and `Sync` calls `FinalPaths` only *after* `Backup` returns. `Discard` is best-effort everywhere it is called. Production adapters are unexported; `export_test.go` re-exports `NewSQLiteSource`/`NewDirDestination` for `snapshot_test`. (SCENARIO-01a, 01b, 08, 11)
- `Manifest.Encode()` is the only encoder (2-space indent, trailing `\n`); the four diff lists are always non-nil empty slices, never `null`. (SCENARIO-01a)
- `Sync`'s order: reference check → `Source.Open` → `Probe` → `Destination.Prepare` → `Backup` → integrity check → `ZACCOUNT` exists → count ≥1 → SHA-256 → schema diff → `Encode` → `WriteManifest` → single pre-commit ctx check → `CommitManifest` → `CommitSnapshot` (extracted into `Server.commit`). `ResolveBundlePath`'s header-byte check (R8b, in `validateData`) runs before any SQLite open, ahead of all of this. Every pre-commit failure site (`Open`/`Probe`/`Prepare`/`Backup`/`buildManifest`/`WriteManifest`) is routed through `failureOutcome(ctx, refusal)`, which substitutes `InterruptedRefusal()` (I1) whenever `ctx.Err() != nil` — so a cancelled run reports I1 instead of whatever refusal the step would otherwise classify to. The one dedicated check ahead of `commit`'s renames is separate: once it passes, both renames run to completion regardless of ctx. (SCENARIO-01a, 08, 11, 13, final-gate REVIEW-01)
- `Sync` takes an already-resolved, absolute bundle directory path and joins `"data"` itself; it never resolves `~` or relative paths itself. (SCENARIO-01a, 01b)
- `internal/cli`: `Execute(ctx, args, stdout, stderr, srv, home) error` builds a fresh `*cobra.Command` tree per call. `UsageError{msg}` is a final exit-2 message; `runtimeError` (unexported, `Unwrap`) marks a pre-classified failure so `Execute` returns it unchanged. `sync.go`'s `RunE` renders the whole output into a string first, then makes one `cmd.OutOrStdout()` write; a write failure returns `&runtimeError{fmt.Errorf("write output: %w", err)}` (exit 1) before warnings are printed. Root: `SilenceUsage`/`SilenceErrors`/`DisableSuggestions` true, no `Run`/`Args` on root. (SCENARIO-01b, final-gate REVIEW-01)
- `internal/snapshot.ResolveBundlePath(home, path)` resolves a `--quicken` value: `homepath.Expand` → `filepath.Abs` → `os.Stat` → `.qdf`/`.QDF` → not-a-directory → `validateData` (data file readable, then its header bytes 18-19 checked for a WAL format-version with no live `data-wal` sibling — R8b). `DiscoverBundle` skips a candidate only on `errors.Is(err, fs.ErrNotExist)` (a dangling symlink); any other stat fault (e.g. a symlink loop) is `unreadableRefusal`, not a silent skip. `RefusalError` (value type, `Error()` excludes the `quarry: ` prefix) is every final refusal's shape. (SCENARIO-05, final-gate REVIEW-01)
- `internal/platform/homepath` (`Expand`/`Abbreviate`) is the one seam for home-relative path text. (SCENARIO-05)
- `Server.home`/`Server.busyTimeout` (default 5s) are `Server`'s two extra fields; `busyTimeout` governs both `Source.Open`'s connection busy_timeout and `Source.Backup`'s Go-level retry deadline. Not a CLI flag or config key in Phase 0. (SCENARIO-06)
- `sqlite.Backup`/`runBackup` retry on a not-done/no-error `Step`: sleep 10ms via a ctx-watching `select`, until `busyTimeout` elapses or `ctx` ends. `sqlite.IsNotADB`/`IsBusy` mask a `sqlite3.Error.Code` to its primary byte before comparing, so an extended code (e.g. `ErrBusyRecovery`) still classifies. `tableColumns` wraps `rows.Err()` with the same `"columns of %s: %w"` context every other path uses — a virtual table whose module is absent is a real, if rare, way to reach it. (SCENARIO-06, final-gate REVIEW-01)
- `refusal.go`'s `sourceRefusal(home, bundlePath, err) (refusal error, ok bool)` classifies a `Source` failure as encrypted/busy (`ok=true`) or returns the generic `fmt.Errorf("sync %s: %w", ...)` wrap (`ok=false`); `Open`/`Probe` use the refusal unconditionally, `Sync`'s `Backup` branch checks `ok` to decide between it and `writeFaultRefusal`. `contentRefusal` (content_refusal.go) is the separate, snapshot-copy-facing classifier (R10/R11/R12) — the two must not merge. (SCENARIO-06, 08, final-gate REVIEW-01)
- `destination_refusal.go`'s `causeText(err)` (renamed from two duplicate helpers, `osReason` + `writeReason`) is the one generic unwrap-to-root loop every refusal builder uses. `unwritableDirRefusal` (renamed from `prepareRefusal`) is always a `Prepare` failure; `writeFaultRefusal` (renamed from `writeRefusal`) is every later write failure, itself an `unwritableDirRefusal` when `errors.Is(err, fs.ErrPermission)`. `atomicfile.Commit` treats a successful `Link` as committed even when the follow-up `Remove` of the old partial fails — only `Link`'s own error aborts the commit. (SCENARIO-13, final-gate REVIEW-01)
- `outcome.go`'s `MismatchError` (M1) and `extrasWarningText` (W1) are BR-9's outcome policy. W1's verb/pronoun agree with the singular (`is`/`it`) only when exactly one table-or-column, in total, is unexpected; `1 table and 1 column` still takes `are`/`them`. Both refusal builders share `sqlschema.CountPhrase`. (SCENARIO-10, final-gate REVIEW-01)
- `dirDestination.Backup`'s reservation loop tries `name`, `name_2`, ... uncapped; `Prepare`'s startup sweep removes only quarry-pattern `.partial` leftovers (`leftoverPartialPattern`) older than `leftoverMaxAge` (1h). `WriteManifest` now `f.Sync()`s the partial before an explicit `f.Close()`, returning either's error. (SCENARIO-11, 13, final-gate REVIEW-01)
- `cmd/quarry/main.go` wires `signal.NotifyContext(ctx, os.Interrupt, syscall.SIGTERM)`; a background goroutine calls `stop()` once `ctx.Done()` fires, so a second signal reverts to the OS default (immediate exit) instead of staying diverted forever. `run()` maps a `v9.Reference` failure to `snapshot.InterruptedRefusal()` (I1) when `ctx.Err() != nil` — the one other site (besides `Sync`'s own `failureOutcome`) that can observe a cancelled context before any snapshot work starts. (final-gate REVIEW-01)

## Traps
- mattn/go-sqlite3's `Backup` is called on the **destination** connection: `destConn.Backup("main", srcConn, "main")`, not the other way around.
- A `database/sql.DB` pinned to `SetMaxOpenConns(1)`: never call a method needing a pool connection while a `*sql.Conn` checked out from that pool is still open — it deadlocks.
- SQLite creates db files `0644`; pre-create the partial `0600` via `atomicfile.Create` (`O_EXCL`) before backing up into it.
- The backup API copies the WAL flag from the source header, so the destination needs `PRAGMA journal_mode = DELETE`, or it grows its own `-wal`/`-shm`. The same fact makes a WAL-formatted database's header stay WAL-marked (bytes 18-19 = 2) even after a clean close checkpoints and removes `-wal`/`-shm` — R8b's whole signal. Only `v9fixture.OpenBundle` sets WAL mode, and it never closes before `Sync` runs; a future WAL fixture that does close must account for R8b flagging it.
- `atomicfile.Commit` is hard-link-then-remove, not `os.Rename`; a successful `Link` is the commit, so a failing `Remove` afterward is swallowed, not propagated.
- `os.UserHomeDir()`/`v9.Reference(ctx)` failures happen in `cmd/quarry/run()` before `cli.Execute` runs — routing them through the `UsageError` check would wrongly exit 2 on an unset `HOME`; a cancelled ctx there maps to I1 instead.
- Cobra's `c.Find` failure (unknown command) returns a plain error straight from `ExecuteContext` — `Execute`'s default branch, not a named check, catches it.
- `SilenceErrors`/`SilenceUsage` on the root command alone suppress printing for every subcommand.
- Cobra falls back to reading `os.Args` when `SetArgs(nil)` — `Execute` requires a non-nil `args` slice.
- Don't mark a ctx-consuming call `// unreachable` on the strength of "no external resource can fail" alone — signal handling means a real SIGINT can land there.
- `v9fixture.CorruptDataFile`'s corruption trick only works on a database it built itself; never run it against an existing WAL-open fixture's `data`. A 0-byte `data` file opens, probes and backs up clean; it must never reach `sourceRefusal`'s encrypted branch, and its `n < 20` header read makes R8b's check a no-op for it too. `IntegrityCheck`'s first PRAGMA row is header-plus-detail, plus a second, unread row — never derive a test's expected text by reading `IntegrityError.Result` back from the code under test. A stub (no real `data` file) for a content-rejection row reddens at `ResolveBundlePath`, not at `Sync`'s content checks.
- Every fallible step in `Sync` returns a classified `RefusalError` (or I1); the generic `fmt.Errorf("sync %s: %w", ...)` wrap survives only on the `// unreachable` `Manifest.Encode` branch. A new fallible step must be routed through a classifier and `failureOutcome`, not left bare.
- `ResolveBundlePath`'s readability check is a plain `os.Open`+immediate-`Close` (now also reading the header through that same open), never a second open — closing any fd drops every fcntl lock the process holds, so opening `data` twice would risk dropping SQLite's lock mid-backup.
- `os.Stat` already follows symlinks; `ResolveBundlePath` does not `Lstat` or `filepath.EvalSymlinks`.
- mattn defaults every connection's `busy_timeout` to 5000ms unconditionally; `sqlite3_backup_step` alone is exempt (returns immediately on BUSY/LOCKED). A test wanting a fast, deterministic busy failure through `Backup` must open the source via `OpenReadOnlyBusy` with a small timeout, not plain `OpenReadOnly`.
- A ctx-cancellation test for a retry loop needs the loop actually *waiting* (real contention) when cancel fires; `database/sql`'s `Conn(ctx)` rejects an already-cancelled ctx before the code under test is reached — construct the cancellation via a fake port instead when no real wait exists.
- `BEGIN EXCLUSIVE` must be left **uncommitted** for a lock fixture's whole test.
- M1 and W1 both name the bundle by `filepath.Base`; M1 gives the snapshot `~`-abbreviated, W1 gives the manifest as a bare `filepath.Base`. W1 excludes the *entire* "quarry: warning: " prefix, unlike the error path.
- `ALTER TABLE ... DROP COLUMN` refuses a column that is PK/UNIQUE/FK or referenced by an index/trigger/view — a fixture mutating `v9.ReferenceDDL` must check indexes before picking columns to drop.
- `testing/synctest.Test` works cleanly against this package's real cgo/file-I/O backup path; build the fixture *before* entering the bubble.
- `dirDestination.Backup`'s reservation loop has two independent collision checks (`fs.ErrExist` on create, and an existing final) needing separate tests.
- `os.MkdirAll` returns `nil` for an already-existing directory regardless of permission bits — a write-failure test must pre-create the directory and `chmod` *that*.
- Creating a hard link needs write permission only on the *destination's* parent directory, not the source's — useful for constructing a "link succeeds, remove fails" fixture across two directories.
