## Binding decisions
- `internal/quicken/v9` (+ `v9fixture`) is a data package; production `internal/snapshot` never imports it. The reference schema arrives via `WithReference(label, sqlschema.Schema)`; `cmd/quarry` is now the one production caller of `v9.Reference`/`v9.ReferenceLabel`. (SCENARIO-01a)
- BR-6 scope lives in unexported `snapshot.scopeSchema`; `sqlschema` stays generic (no Quicken knowledge). Fingerprint and diff both run on scoped schemas. `SchemaInfo.ReferenceTables`/`ReferenceColumns` (`json:"-"`) are the scoped reference's counts, computed once in `schemaInfoFromDiff` for the CLI's human Schema line. (SCENARIO-01a, 01b)
- `Source` (`Open`/`Probe`/`Backup`/`Close`) and `Destination` (`Prepare`/`Backup`/`WriteManifest`/`CommitSnapshot`/`CommitManifest`/`FinalPaths`) are the only two ports in `internal/snapshot`. `FinalPaths(name) (snapshotPath, manifestPath string)` is a pure name→path prediction (no collision suffix yet); `Sync` calls it once right after computing `name` and sets `Manifest.Snapshot.Path`/`.Manifest` from it *before* `Encode`, so the bytes committed to disk already carry the paths `Sync` returns (BR-10) — fixes SCENARIO-01a's bug where the on-disk manifest's own path fields were empty. Production adapters are unexported (`newSQLiteSource`, `newDirDestination`); `internal/snapshot/export_test.go` re-exports them as `NewSQLiteSource`/`NewDirDestination` for the `snapshot_test` package only. Both are injectable in production via `WithSource`/`WithDestination`. (SCENARIO-01a, 01b)
- `Manifest.Encode()` is the only encoder (2-space indent, trailing `\n`); the four diff lists are always non-nil empty slices, never `null`. (SCENARIO-01a)
- `Sync`'s order is: reference check → `Source.Open` → `Source.Probe` → `Destination.Prepare` → `Destination.Backup` → integrity check → `ZACCOUNT` count → SHA-256 → schema diff → `Encode` → `WriteManifest` → `CommitManifest` → `CommitSnapshot`. Manifest commits before snapshot (BR-8). Nothing touches the snapshots directory before the probe succeeds. (SCENARIO-01a)
- `Sync` takes an already-resolved bundle directory path and joins `"data"` itself. `internal/cli` passes `--quicken`'s value straight through, unresolved — discovery, `~/` expansion and R4–R7 path validation belong to 04/05. (SCENARIO-01a, 01b)
- `internal/cli`: `Execute(ctx, args, stdout, stderr, srv *snapshot.Server, home string) error` builds a fresh `*cobra.Command` tree per call. `home` is resolved once in `cmd/quarry/run.go` via `os.UserHomeDir()` and passed in — `Execute` never reads the environment; SCENARIO-04/05 reuse the same value. `UsageError{msg}` (value type, not pointer) is a final exit-2 message; `Execute`'s default branch wraps any other cobra-native error (unknown flag, missing value, required flag, unknown command) as `UsageError{err.Error() + "; Run 'quarry sync --help' for usage."}` (U2, orchestrator-accepted wording). `runtimeError` (unexported, `Unwrap`) marks an `srv.Sync` failure as already-classified; `Execute` unwraps it and returns the original error unchanged (exit-1 default in `cmd/quarry`). `--quicken` is `MarkFlagRequired` until SCENARIO-04 adds discovery and removes it (orchestrator-accepted interim state — bare `quarry sync` exits 2, not R1–R3, until then). Root: `SilenceUsage`/`SilenceErrors`/`DisableSuggestions` true, `CompletionOptions.DisableDefaultCmd` true, `help` subcommand kept, no `Run`/`Args` on root itself (orchestrator-accepted). (SCENARIO-01b)
- `internal/cli/render.go`: `renderSuccess` covers the exact-match Schema line only (`matches reference <label> (T tables, C columns)`); missing/unexpected-table rendering is SCENARIO-09/10's. Labels are `%-10s` left-padded; `formatThousands` assumes non-negative input (this package's only callers are byte/account/table/column counts). (SCENARIO-01b)

## Traps
- mattn/go-sqlite3's `Backup` is called on the **destination** connection: `destConn.Backup("main", srcConn, "main")`, not the other way around.
- A `database/sql.DB` pinned to `SetMaxOpenConns(1)`: never call a method that needs a pool connection while a `*sql.Conn` checked out from that same pool is still open — it deadlocks. Run the follow-up statement through the checked-out `*sql.Conn` itself.
- SQLite creates db files `0644`; pre-create the partial `0600` via `atomicfile.Create` (`O_EXCL`) before backing up into it.
- The backup API copies the WAL flag from the source header, so the destination needs `PRAGMA journal_mode = DELETE` before hashing, or it grows its own `-wal`/`-shm`.
- `atomicfile.Commit` is hard-link-then-remove, not `os.Rename` — refuses to clobber an existing destination atomically.
- Corrupting a SQLite file to fail `integrity_check` needs real page content — see `internal/snapshot/sync_faults_test.go`'s `newIndexCorruptedSnapshot` for the recipe (build the queried table first and small, corrupt a separately-indexed filler table's last pages).
- `dirDestination.WriteManifest`'s `f.Write(data)` failure branch is permanently unreachable through the real adapter; marked `// unreachable` in code, not an open debt.
- `os.UserHomeDir()`/`v9.Reference(ctx)` failures happen in `cmd/quarry/run()` before `cli.Execute` runs — routing them through the `UsageError` check would wrongly exit 2 on an unset `HOME`.
- Cobra's `c.Find` failure (unknown command) returns a plain error straight from `ExecuteContext` — `Execute`'s default branch, not a named check, catches it. Without `DisableSuggestions` on root, a near-miss like `synk` would append `"\n\nDid you mean this?\n\tsync"`, breaking the one-stderr-line rule.
- `SilenceErrors`/`SilenceUsage` on the root command alone suppress printing for every subcommand (cobra checks the root's flags, not the found command's).
- Cobra falls back to reading `os.Args` when `SetArgs(nil)` — `Execute` normalizes `nil` args to `[]string{}` before `SetArgs`.
