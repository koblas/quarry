## Binding decisions
- `report.Classification{Registered, NonRegistered []string}` is passed INTO `(*report.Server).Accounts`; `report` owns the rule via `Classification.Of(store.Account) *bool` (true listed registered / false listed non-registered / nil neither) and `Classification.Unclassified(a)` (investment type and in neither list). S04/S05 reuse these two so every site agrees (SCENARIO-01)
- An id in both `accounts.registered` and `accounts.non-registered` is REFUSED by `config.Load` (`(document).notInBoth`, after both `idList` calls; names the first registered id in file order, masked, ` in both`). `Classification.Of`'s registered-first order is now only a tie-break for hand-built values, unreachable from a config (SCENARIO-02)
- `Config.Registered` / `Config.NonRegistered` keep file order, duplicates and spelling as written (case-sensitive: `Acct-3` is not `acct-3`); S03's unknown-id warning reads them raw (SCENARIO-01, 02)
- `accountmask.Mask(s)` (`internal/platform/accountmask`) is the one masking helper; exported so S05's unmatched warning calls it on the raw id (`lists "<Mask(id)>"`), never a copy. Digits counted across the WHOLE string (`unicode.IsDigit`), all but last four become `*`, other runes kept; exempt only exact `^acct-[0-9]+$`. Per-run counting would leak `1234 5678 9012` (SCENARIO-02)
- Masking is per-setting: `setting.masked` is set only on `registeredSetting`/`nonRegisteredSetting`; `findings.ignore`, keep, path, currency echoes stay raw. Masked sites: `idList` got text and item text (masked BEFORE ` as item n`), `lookup` (`accounts must be a table`), `keyText` for parts after `accounts` (unknown-key warnings, both `Warnings` and `WarningsAbsolute`), and `tree()` via `maskNamedKey` for the four go-toml shapes that echo a key/table name (`key N is already defined`, `key N should be a table, not a value`, `table N already exists`, `... as an array of tables`) only. MCP gets the same text via `Problem`/`ProblemAbsolute` (SCENARIO-02)
- Config parsing: one `document.idList(setting, noun, example)` shared by `findings.ignore` and the two account lists; parsed after `currency()`, before unknown keys; `[accounts]` table and dotted forms both load (SCENARIO-01)
- `accounts` always loads the config, even with `--currency` (`readConfig` + `currencyFlag.in(cmd, cfg)` in `internal/cli/currency.go`); the other six `currencyFlag` commands skip the loader when the flag is given (pinned in `currency_test.go`). Warnings print once (SCENARIO-01)
- Status words append last, after `linked tracking`: `registered` then `unclassified`; JSON `registered` (`*bool`, null when neither) sits right after `linked_tracking` (SCENARIO-01)
- The "registered is not in the store" sentence ends `report.SQLConventions`; S06's cost_basis sentence goes in the investment paragraph / after it. `schema.md` is regenerated by `go test ./cmd/quarry -run Test_skill_schema_reference_matches_the_committed_file -update`, never hand-edited (SCENARIO-01)

- Narrow-loop `-run` is case sensitive: `-run 'Both'` misses lowercase `_both_` names, `'Account'` misses `Test_accounts_...`; use `-run 'ccount'`, `'(?i)both'` or the exact test name, or the acceptance test appears not to run (SCENARIO-01, 02)

- `Server.Accounts` filters closed accounts after the read; classification applies to the rows that remain, and `Hidden` stays a count of closed accounts only (SCENARIO-01)
- A non-investment account in neither list has empty Status and JSON `null`, not `false`; only a listing in `accounts.non-registered` gives `false` (SCENARIO-01)
