## Binding decisions
- Rates port, frozen (03 filled its fields; never reshape): `duckstore.RatesSource{Refresh(ctx, store.RatesRequest) (store.RatesRefresh, error)}`; `store.RatesRequest{Need, Have DateSpan}` (zero = empty); `store.RatesRefresh{Rates []Rate; Added int; FetchError string; Partial bool}`; `store.Rate{Date, USDCAD money.Rate, Series}`. Types live in driver-free `internal/store`, so `*fx.Server` satisfies the port directly (guard `_ duckstore.RatesSource = (*fx.Server)(nil)` in `cmd/quarry/run.go`); fx never imports duckstore. Series names are `store.SeriesCurrent` (FXUSDCAD) / `store.SeriesLegacy` (IEXE0101) (SCENARIO-07, 01, 04)
- fx package shape: `Server` + `Option`s `WithHTTPClient`, `WithSource`; `Source{Observations(ctx, series, span)}` is fx's own port to the publisher (Go errors); `Valet` is the Bank of Canada adapter (`valet.go`, `testdata/valet_*.json`); `plan.go` `planSpans` splits Need minus Have into head/tail spans; IEXE0101 only for a head/first-sync span, for days before the first FXUSDCAD date in that answer (cutover is data); tail span never asks legacy. Rates leave Refresh sorted, none <= 0 (DECIMAL(10,6) bound enforced in Valet), none inside Have, `Added == len(Rates)` (SCENARIO-01)
- Refresh contract: non-nil error ONLY when the PARENT ctx ended, classified by `ctx.Err()` after each span (never `errors.Is(err, DeadlineExceeded)`); every other Source failure -> `FetchError` = the ruled `<reason>`, nil error, store still swapped. A parent cancel keeps the previous store. Network data must never fail the build: PK/CHECK violations are filtered or refused in fx. Carried and fetched rows must never share a date; "none inside Have" plus Have ⊇ every carried date is the only guard (SCENARIO-07, 01, 04, 03)
- Fetch reasons (`fx/reason.go` `fetchReason`, ruled): `cannot reach www.bankofcanada.ca` (dial fault, body read fault, any unclassified Source error = `default:`), `no answer from www.bankofcanada.ca within 30 seconds`, `www.bankofcanada.ca answered <code> <StatusText>` (from `StatusCode`, never `resp.Status`; no text = code alone), `www.bankofcanada.ca sent an answer that is not a list of exchange rates` (bad JSON, impossible rate, body over `maxAnswerBytes` = 16 MiB). Timeout = child `context.WithTimeout(ctx, requestTimeout)` per Source call in `(*Server).observe`, so it covers every Source; classified after the parent check: child ctx expired OR `errors.Is(DeadlineExceeded)` (a stalled body drops the cause) (SCENARIO-03)
- Stop rule: after a timeout or an unreachable bank the later spans are NOT asked (each would wait as long); after a status or not-rates failure they are (<=3 requests, <=90 s). FetchError = the FIRST failure's reason (SCENARIO-03)
- Partial semantics: keep is per Source answer. Failed FXUSDCAD keeps nothing of its span; failed IEXE0101 keeps that span's FXUSDCAD rates. `Partial` = FetchError set and >=1 rate kept; `Added == len(Rates)`. Kept rates are adjacent to Have or start a fresh Have at the cutover, so Have stays one interval and Have.Last never lands in the legacy era. `rates_checked_from` never advances on any FetchError, partial included: the answered head is re-asked next sync (SCENARIO-03)
- `import_runs.rates_fetch_error` IS written by `duckstore` `recordRates` (reason, NULL on success or when nothing asked); 06's status clause reads it. `store.RatesSummary` carries `FetchError` and `Partial` to snapshot and cli (SCENARIO-03)
- Replace order: build -> readHistory -> Refresh (Need.First = earliest transaction, Need.Last = today's LOCAL date) -> append carried then fetched fx_rates -> UPDATE the new import_runs row -> store_info -> CheckpointClose -> ctx gate -> rename; the UPDATE is inside temp-then-rename, so its fault keeps the previous store. `duckstore.WithRates(src)`; without a source the carry still happens. `cmd/quarry/run.go` `newRatesSource` (default `fx.NewServer()`) is the one network seam (SCENARIO-07, 01, 04)
- Carry (04): `readHistory` is a 6-query read on a full store (import_runs columns+rows, findings columns+rows, fx_rates columns+rows); fx_rates is read after findings and fails on its own (`Result`/`Replaced.RatesFault`), exactly like `FindingsFault`; a lost run history does not lose rates. usd_cad is read as exact millionths (`CAST(usd_cad*1000000 AS BIGINT)`), never float. An absent fx_rates table (v4) = nothing carried, silently. A repeated date, NULL/missing cell, rate <= 0 or out of range, or a series other than FXUSDCAD/IEXE0101 makes the table unreadable: nothing carried, the rest of the history still carried (SCENARIO-04)
- Have and floor (04): `Have` = [earliest(floor, first carried rate), last carried rate], ZERO when no rates were carried (an empty answer is re-asked in full next sync, one request). `floor` = newest non-NULL `rates_checked_from` by run id. `import_runs.rates_checked_from` = earliest(previous floor, Need.First) when this run asked with no FetchError and Need non-empty; otherwise the previous floor carried (FetchError, no transactions, no source); NULL only if never answered. `rates_last` = max(fx_rates.date). An unreadable fx_rates resets the floor to zero (it would claim dates whose rates were lost); an absent or EMPTY fx_rates keeps the floor in the written column even though Have is zero. Plan deviation: the plan read "floor ignored when no rates carried" as covering the column too; built, it governs Have only (SCENARIO-04)
- Warning (ruled, spec R7): `cannot carry exchange rates forward from the previous store (<reason>); fetching them all again`. Reasons: `its fx_rates table repeats a date`, `... holds an impossible rate`, `... names an unknown series`, `... is incomplete` (NULL cell, missing column, any other read failure). Whole-store-unreadable prints ONLY the combined line `cannot carry import history, findings or exchange rates forward from the previous store (<reason>); all three start again with this sync`, no rates line; v4 silent. Order in stderr and `warnings[]`: manifest, history, findings, rates, prune; exit 0, rates refetched in full (SCENARIO-04)
- `RatesFault` flows `duckstore.Replace` -> `importer` -> `snapshot.Outcome.Warnings()` (`ratesRestartWarning`, `combinedCarryWarning`, `carryWarnings` in `snapshot/import.go`) (SCENARIO-04)
- Fetch warning (ruled, one per sync, `snapshot.Outcome.fetchWarning` from `RatesSummary`; dates `time.DateOnly`): nothing stored `could not fetch exchange rates from the Bank of Canada: <reason>; the store has no rates, so reports list amounts in each account's own currency; run quarry sync again to retry`; nothing new `... <reason>; the store has rates from <first> to <last>, and later dates convert at the <last> rate; run quarry sync again to retry`; partial `could not fetch every exchange rate from the Bank of Canada: <reason>; the store has rates from <first> to <last>; run quarry sync again to fetch the rest`. Order in stderr and `warnings[]`: manifest, history, findings, rates-carry, rates-fetch, prune; the combined carry line precedes it too. `--json` also echoes each warning on stderr (SCENARIO-03)
- Rates line arms: partial `(<n> new, not all fetched; see warning)` (checked before FetchError in `ratesPhrase`), nothing new `(not refreshed; see warning)`, no rates `none (not fetched; see warning)`; `--json` partial gives `added: n` and `fetch_error` set. A sync failing before the swap fetches nothing (`Replace` asks for rates only after a successful build) and prints no Rates line (SCENARIO-03, 05)
- Schema v5 (`FormatVersion` 5): `fx_rates(date PK, usd_cad DECIMAL(10,6) CHECK > 0, series)`; import_runs +`rates_checked_from`, `rates_last`, `rates_fetch_error` (28 cells). v4->v5 carry fills NULL (SCENARIO-07)
- Rates line and JSON: `Rates     USD/CAD <first> to <last> (<n> new)` / `(up to date)` (first/last from min/max(fx_rates.date), so carried rates with no transactions still print); failure arms below. Sync `--json` `store.rates` `{first,last,added,fetch_error}` last key of `store`, null when no store was built (SCENARIO-01, 04)
