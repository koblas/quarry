# SCENARIO-11: A Claude Code failure does not stop Claude Desktop, an interrupt does

Cadence: code-first — no mandatory item touched (D13 guard stops a write, it does not protect user files; the write guards it sits beside are SCENARIO-02/13's, unchanged)
Acceptance test: `internal/cli/claude_continue_test.go` `Test_claude_install_installs_claude_desktop_after_a_claude_code_failure` (rows: foreign marketplace, step exits non-zero, unreadable list; asserts Code line on stderr in place, Desktop added, config written, `ReportedError`). The two interrupt rows have their own tests in Build.
Narrow loop: `go test -timeout 60s ./internal/claudedesktop/ ./internal/cli/ -run 'Interrupt|Cancel|Continue|After_a_claude_code|Test_claude_install|Test_claude_uninstall|Test_install|Test_uninstall'`
Mutation checks: ctx check before the backup in `(*Server).Install` → `Test_install_stops_before_writing_when_the_context_is_cancelled` | same in `(*Server).Uninstall` → `Test_uninstall_stops_before_removing_when_the_context_is_cancelled` | `*claudeplugin.InterruptedError` stop in the continue helper → `Test_claude_install_does_not_touch_claude_desktop_after_an_interrupt_during_a_code_step` | helper returning nil after a successful Desktop step (drops the Code failure) → the acceptance test
Runs: A (1) | B1 (2-3) | B2 (4) | V (5-6)
Size: OWNS A RUN — 3 batches, 1 feature package (`internal/claudedesktop`; cli and wiring tests do not count)

User contract (copy verbatim from spec §D, D13; BR-D13/D16/D19, both verbs): a Code failure prints its unchanged line on stderr in place (an unclassified error now `quarry: claude <verb>: <lead><err>` and `ReportedError`, no `runtimeError`), then Desktop runs as usual and prints its own stdout/stderr lines; exit 1 whatever Desktop does. `*claudeplugin.InterruptedError` ends the run, Desktop not attempted. Interrupt after Code finished: Code lines stay, then D13 on stderr, config and backup untouched, exit 1. A stdout write error while printing the finished steps returns that error at once (no Desktop, not `ReportedError`). Port survey: n/a, no new port; `Server.Install/Uninstall` already take `ctx`, ignoring it (`claudedesktop.go:237`, `:329`).

## Handoff

**Binding decisions:**
- Every Code failure prints in place and Desktop then runs, except `*claudeplugin.InterruptedError` (Desktop never attempted) and a failed stdout write of the finished steps (returned at once) — BR-D13 exit 1 is carried by returning the Code `ReportedError` after Desktop; Desktop's own error wins when it has one.
- D13 is `claudedesktop.ErrInterrupted` from the ctx check just before the backup, so only a write that would have happened is refused; `Unchanged`, DN and skips never print D13.
- `reportClaudeFailure` no longer returns `runtimeError`; `Test_claude_*_returns_the_runners_own_error…` pins are rewritten, not deleted.

**Left unbuilt:** help Long for install/uninstall/mcp, README, PRD — SCENARIO-16. Desktop's own `runtimeError` arm in `reportDesktopFailure` (`render_claude.go:267-271`) stays: BR-D16 names only the Code arm.

**Traps:**
- A Desktop-absent test home makes every Code-failure stdout gain S2: `Empty(stdout)` rows must change, interrupt rows must not (their emptiness proves Desktop was not attempted).
- A `/home/ada` home in a Code-failure test now stats a real path; use `t.TempDir()`.
- `ctx.Err()` read from a `Server` built in a test with a default context never fires D13; cancel the context the command runs under (`toolCalls.cancel`).
